# PageLingo 浏览器回归与速度基准

用户安装仍然只需 `edge-translator.user.js`。以下依赖仅用于开发验证。

## 运行

使用 Node.js 18 或更高版本：

```sh
npm ci
npm run check
npm test
npm run bench
```

测试优先使用 Windows 常见路径下的 Edge。可用环境变量 `PAGELINGO_BROWSER_PATH` 指向自己的 Edge/Chromium；若没有 Edge，先运行 `npx playwright install chromium`。

浏览器中的外部网络请求被拦截，`GM_xmlhttpRequest` 使用模拟响应，Key 测试使用明确的虚构字符串。真实服务请求不属于自动化测试。

## 断言内容

`translation.cjs` 包含 79 个测试：

- 导航、按钮、菜单、标签页、单字母短词、行内兄弟节点和大块前后的零散文字；中文语言标记中的混合外文。
- 提示属性与正文合并请求和去重；搜索提示、无障碍标签、下拉选项、纯属性页面、动态更新、过期响应、还原和取消。
- 翻译后导航链接、按钮事件和图标可用，代码及不翻译部分保留；关闭菜单和 CSS 隐藏内容显示后再翻译，属性遵守视口范围，移除节点释放引用。

- 不滚动也能翻译普通页面全部 120 段，并确认只发送一次微软请求。
- 同一轮跨多个批次、缓存命中混合、仅译文模式都在完成后统一显示。
- 大页面请求严格限制为初始视口内文本，滚动后续译，初始位于底部时不先请求顶部。
- 文本量和段落量两个规模阈值，以及动态增长后切换到视口范围。
- 切换语言、停止、退避取消、后台暂停、优先划词、原文在等待期间变化。
- 413/414 策略中的 413 缩批路径、微软到 DeepL 的重新拆包、固定 DeepL 批量、429 等待。
- 恢复原文、链接保留、隐藏文本和表单过滤、Key 保护、缓存接口隔离、动态节点清理和频繁变化保护。
- Google 120 段单次 POST、长文本与表单保留字符、两种数组响应、数量不符/空值/HTML 字符串防护。
- 自动择快、快速成功不探测、网络失败立即换线、学习成功线路、停止时取消两条线路和延迟计时器、413 缩批，DeepL 不参与探测。
- 真正重新加载页面后复用 GM 缓存、缓存到期/损坏/关闭/清除，没有 GM 存储时不写网站 localStorage。
- 双语/仅译文切换不扫描或发请求，翻译中切换不取消工作，以及真实鼠标单击翻译/恢复、右键设置。

测试在内存副本中添加 `__TEST` 导出以读取状态，安装脚本不包含该导出。`MutationObserver` 记录实际译文插入后的数量，验证多个请求没有逐批显示。

## 速度基准

```sh
npm run bench
# 对比其他本地 Git 提交：
node tests/benchmark.cjs <commit-or-tag>
```

默认基线为 v0.6.0 的 `674b3a0`。两版使用相同正文和 1280×900 视口，都开启强制整页以保持工作量一致，分为四组：

| 场景 | 内容 | 模拟响应 |
| --- | --- | --- |
| Google 批量 | 24 段 | 每次 600ms |
| 自动模式慢主线路 | 120 段 | 微软 2500ms，Google 150ms |
| 微软批量 | 120 段 | 每次 600ms，确认原批量能力 |
| 刷新后缓存 | 120 段 | 首次完成后重新加载；每次请求 600ms |

每组每版运行 3 次并交替次序，报告从开始翻译到最后一次实际 DOM 插入的中位耗时，同时记录首批显示、请求数、在途并发数和各次显示的段落数。刷新组会重新创建页面上的脚本和模拟 GM API，保留同一个管理器存储快照。原始结果写入 `tests/results/benchmark.json`，该目录已被 Git 忽略。

模拟基准用于比较脚本调度和显示策略，不能证明真实服务的响应速度，也不能代替油猴和脚本猫扩展内的安装与权限验收。
